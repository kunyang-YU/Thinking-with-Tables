# Thinking with Tables (TWT)

> **Thinking with Tables: Enhancing Multi-Modal Tabular Understanding via Neuro-Symbolic Reasoning**
> A code-based neuro-symbolic reasoning framework for Tabular-Vision Multi-Modal Understanding (TVMU) tasks.

As defined in the paper, TVMU (Tabular-Vision Multi-Modal Understanding) aims to parse table structures from document images or scans, jointly leveraging table-related visual information and textual context to perform table parsing, information extraction, and complex numerical/logical reasoning. It primarily covers two categories of tasks: **Multi-Modal Table QA** and **Multi-Modal Table Prediction**.
**Specifically**, in this repository:

- **Multi-Modal Table QA**: The model is only provided with table header/snippet images + textual descriptions + the raw table file path in the external environment. The model must generate code to read and manipulate the full table in a sandbox to perform lookups, aggregations, computations, and other reasoning;
- **Multi-Modal Table Prediction**: The model is provided with sample images + metadata/task descriptions + table/CSV paths. The model must jointly model tabular features and image features, and complete feature engineering and prediction through code executed in a sandbox.

This README mainly describes **the inference pipeline and usage of the TWT model**.

## 2. Inference Mechanism Overview

TWT uses **program-aided neuro-symbolic reasoning**: the model completes table understanding and QA/prediction through **multi-turn interactions** with the environment (sandbox).

### 2.1 Output Protocol

The model must output in the following format for parsing and sandbox integration:


| Tag                              | Description                                                                           |
| -------------------------------- | ------------------------------------------------------------------------------------- |
| `<analy>...</analy>`             | Reasoning process and problem analysis                                                |
| `<code>...</code>`               | Python code to be executed in the sandbox                                             |
| `<code_result>...</code_result>` | Execution result returned by the sandbox (injected by system, not generated by model) |
| `<answer>...</answer>`           | Final answer                                                                          |


### 2.2 Inference Loop (Single Sample)

```
┌─────────────────────────────────────────────────────────────────────┐
│  Input: Image (table header/sample) + Question/Task description     │
│         + Table/data path, etc.                                     │
└─────────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────────┐
│  Model generates → If <code> appears, extract code → Execute in    │
│  sandbox → Get <code_result> → Append to conversation context →    │
│  Call model again … Until <answer> appears in response, parse to   │
│  obtain the final answer.                                          │
└─────────────────────────────────────────────────────────────────────┘
```

In short: **each turn** the model can output `<analy>` + `<code>`; the system executes the code and feeds the result back as `<code_result>`; this repeats until the model outputs `<answer>`.

### 2.3 Sandbox Execution

This repository includes **all tools required for inference on the datasets in the paper** (e.g., table data paths, ResNet50 weights, and `tools.py`), ready for reproducing experiments.

Code is executed in a **controlled sandbox** (with timeout, persistent `env`). The core logic is equivalent to:

- **Table QA**: Only requires a Python environment capable of executing pandas and other table reading/computation libraries.
- **Table Prediction**: The sandbox must be able to `from tools import ResNet50Predict`, with the directory containing `tools.py` added to `sys.path` (or equivalent); the `task` and weight path in `ResNet50Predict(task, image_path)` must match the current task (e.g., `pawpularity`, `adoption`, `skinca`, `paintings`).

## 3. Training Process (SFT & GRPO)

TWT follows the two-stage training described in the paper: **Task-Oriented SFT (TO-SFT)** and **Adaptive Loss-Scaled GRPO (AL-GRPO)**, both implemented under the Swift framework.

### 3.1 Task-Oriented SFT (TO-SFT)

**Approach**: Perform task-oriented supervised fine-tuning on a base multi-modal model (e.g., Qwen3-VL-8B), teaching the model to output in the `<analy>` / `<code>` / `<answer>` format and master the basic solving process for both Table QA and Table Prediction tasks. During training, code execution results (`<code_result>`) are **masked** — loss is only computed on model-generated text and code sequences to prevent memorizing execution results.

**Dataset Structure**: Each sample is a single-turn conversation, formatted consistently with Swift multi-modal SFT. Example fields:

Data sources include: Table QA synthetic data (e.g., `tableqa-python-1interaction.json`, `full-table-inter.json`), multi-modal table prediction data (pawpularity, adoption, paintings, skinca JSON files). The data synthesis pipeline is described in the paper and appendix (LLM-generated reasoning traces + answer verification).

```json
{
  "question": "<image>\n\n### **Question**\nwhat is the percentage of women spoke with family members in the past 12 months of 2018?\n\n### Table file path: your_path/67.csv\n",
  "response": "<analy>...</analy>\n<code>import pandas as pd\n...</code>\n<code_result>...</code_result>\n<analy>...</analy>\n<answer>44.0</answer>\n",
  "image": ["your_path/67.png"]
}
```

**Code Locations**:

- Swift SFT entry: `swift sft` (provided by ms-swift);
- SFT script in this repo: `src/sft1.sh`;
- System prompt (output format specification): `src/prompt.txt`;

**Example Usage**:

```bash
cd src
bash sft1.sh
```

Key parameters in `sft1.sh`: `--model` base model path, `--dataset` multiple JSON paths (Table QA + Table Prediction), `--system` pointing to `prompt.txt`, `--train_type full`, `--freeze_vit true`, `--num_train_epochs 3`, `--learning_rate 1e-5`, `--deepspeed zero3`, etc. Adjust `CUDA_VISIBLE_DEVICES`, `per_device_train_batch_size`, `gradient_accumulation_steps` as needed.

### 3.2 Adaptive Loss-Scaled GRPO (AL-GRPO)

**Approach**: Perform GRPO reinforcement learning on the checkpoint from TO-SFT. The model generates multi-turn responses (containing `<code>`) following the prompt; through the **TWT multi-turn scheduler**, after each generation turn, code is extracted, executed in the sandbox, and the `<code_result>` is appended to the context for continued generation, until `<answer>` appears. Rewards are based on **final answer correctness** (e.g., matching rules for QA, 0/1 for classification, continuous reward for regression); an **adaptive loss-scaled** strategy is adopted: only code segments that **execute successfully** participate in the GRPO loss — failed executions do not backpropagate gradients, improving code stability and avoiding reward hacking.

**Dataset Structure**: Each sample contains **messages + image path + solution (ground truth) + type (task type)**, used for reward computation and multi-turn rollout.

**Field Examples (Table QA)**:


| Field      | Description                                                                                                                                                                  |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `messages` | `[{ "role": "system", "content": "output format specification" }, { "role": "user", "content": "### **Image** <image> ... ### **Question** ... ### Table file path: ..." }]` |
| `images`   | List of image paths, corresponding to `<image>` in the user message                                                                                                          |
| `solution` | Ground truth answer (for reward computation)                                                                                                                                 |
| `type`     | Task type: `TAT-QA` / `FinQA` / `HiTab` / `CLS` / `REG`, determines evaluation method in twtplugin                                                                           |
| `question` | Original question text (optional, for reference)                                                                                                                             |


```json
{
  "messages": [
    { "role": "system", "content": "You are a helpful assistant. ... <analy>...</analy> <code>...</code> <answer>...</answer>" },
    { "role": "user", "content": "### **Image**\n<image>\n\n### **Question**\nHow much is the 2019 rate of inflation?\n\n### Table file path: your_path/1.csv\n" }
  ],
  "images": ["your_path/images/1.png"],
  "solution": "2.9",
  "type": "TAT-QA",
  "question": "How much is the 2019 rate of inflation?"
}
```

**Field Examples (Table Prediction)**:


| Field      | Description                                                                               |
| ---------- | ----------------------------------------------------------------------------------------- |
| `messages` | system + user (user contains `<image>`, task description, `image path:`, `tabular path:`) |
| `images`   | List of sample image paths                                                                |
| `solution` | Regression value or classification label (string, e.g., `"3"`, `"33"`)                    |
| `type`     | `REG` (regression) or `CLS` (classification)                                              |


```json
{
  "messages": [
    { "role": "system", "content": "You are a helpful assistant. ... <answer>...</answer>" },
    { "role": "user", "content": "## Question\n\nYou are given an image related to pet pawpularity. ... The image is <image>\n\n## Instructions\n... ResNet50Predict(task, image_path) ...\n## Files\n\nimage path: your_path/pawpularity/dataset/images/0c282c8a762452f9110e1f88c1ed01a6.jpg\ntabular path: your_path/train.csv\n" }
  ],
  "images": ["your_path/pawpularity/dataset/images/0c282c8a762452f9110e1f88c1ed01a6.jpg"],
  "solution": "3",
  "type": "REG"
}
```

Table prediction data follows the same structure as the example above — simply modify `solution` and `type` to adapt to different tasks.

**Code Locations**:

- GRPO entry: `src/rl/myrlhf/ms-swift/scripts/rl.sh` (internally calls `scripts/rlhf_ds.py`, equivalent to `swift rlhf --rlhf_type grpo`);
- TWT plugin (multi-turn scheduling + reward format): `src/rl/myrlhf/ms-swift/examples/train/grpo/plugin/twtplugin.py`
  - `TwTMulltiTurn`: multi-turn scheduling, extracts `<code>`, calls `_repl_code_run`, writes `<code_result>` back to `infer_request.messages`;
  - `CodeFormat` (registered as `re_format`): parses `<answer>` from generated content, calls the corresponding evaluation function by `type` (TAT-QA / FinQA / HiTab / CLS / REG), and returns the reward;
- Sandbox & ResNet50: `_repl_code_run` in `twtplugin.py`; table prediction requires `tools.ResNet50Predict` to be importable in the runtime environment, see `src/rl/myrlhf/ms-swift/examples/train/grpo/plugin/tools.py`;
- Adaptive loss-scale: `--loss_scale 'default+code'` is parsed by `get_loss_scale` in `swift/plugin/loss_scale/loss_scale.py`, implementing the strategy of "only backpropagating gradients for successfully executed code segments";
- Launch script: `src/rl/myrlhf/ms-swift/scripts/rl.sh`.

**Example Usage**:

```bash
cd src/rl/myrlhf/ms-swift
# 1) First start the vLLM service, loading the SFT checkpoint (see in-script comments or vllm.sh)
# 2) Modify --model, --external_plugins, --dataset, --output_dir, --resume_from_checkpoint etc. in scripts/rl.sh
bash scripts/rl.sh
```

Key parameters in `rl.sh`: `--rlhf_type grpo`, `--external_plugins` pointing to `twtplugin.py`, `--reward_funcs re_format`, `--multi_turn_scheduler twt_scheduler` (registered by the plugin), `--dataset` as multiple RL JSON files (e.g., under `data/RL_data/WTQdata/` and `data/RL_data/MMData/`, each `train.json`), `--stop_words '</code>' '</answer>'`, `--loss_scale 'default+code'` (adaptive loss-scaled), `--num_generations 4`, `--learning_rate 5e-7`, etc. Before training, ensure vLLM has loaded the correct model and is accessible at `--vllm_server_port`.

All training data used in the paper will be open-sourced along with the code: SFT stage ~**1.5K Table QA + 1.2K Table Prediction + 5.0K additional data**, GRPO stage ~**0.5K Table QA + 0.4K Table Prediction**.

## 5. Running Inference / Evaluation

Before running evaluation scripts, ensure that **all resource paths (table CSVs, images, `tools.py`, ResNet50 weights, etc.) are correctly set for your local environment**, so the sandbox can properly access all files.

### 5.1 Table QA (e.g., TAT-QA)

1. Start the vLLM service (see above), note the `--port` (e.g., 8160).
2. Prepare data: containing `question`, `paras` (optional), table CSV paths, corresponding image paths, etc., formatted consistently with `evaluation/TAT-QA/test.json` and the paths in the script.
3. Run the evaluation script (modify `file_path`, `path`, `image_path` in the script according to your actual paths):

```bash
cd evaluation/TAT-QA
python evaluation_tat.py --exp my_run --model_name twt --port 8160
```

The script will:

- Read each sample's image and question;
- Construct the user message with "image + table path + instructions" following the prompt in the paper;
- Loop: call the local OpenAI client (`base_url=http://127.0.0.1:{port}/v1`), receive streaming response -> extract `<code>...</code>` with regex -> call `sandbox_run(env, code)` -> append the result as `<code_result>` to context and request again, until `<answer>` appears in the response;
- Parse the answer from `<answer>` and write to `output_{EXP_NAME}_{MODEL_NAME}.json`.

### 5.2 Table Prediction (e.g., Pawpularity / Adoption / SkinCA / Paintings)

Using Pawpularity as an example, the script is under `evaluation/multi-modal-evaluation/pawpularity/`:

1. Data: each entry in the JSON contains `image_path`, `instructions` (task description and table/data paths), `answer` (ground truth), etc.
2. Same as Table QA: uses the OpenAI-compatible API + streaming; each turn extracts `<code>`, **prepends** `from tools import ResNet50Predict` before execution in the sandbox (consistent with `twtplugin.py`).
3. The sandbox must be able to import `tools`, and the weight path in `ResNet50Predict` must match the current task (e.g., `pawpularity` / `adoption` / `skinca` / `paintings`).
4. Loop until `<answer>` appears, parse the numerical answer, and save.

Before running:

- Prepare `tools.py` in the corresponding task directory (or ensure its path is in `sys.path`);
- Modify data paths (e.g., `file_path`) and port parameters in the script.

```bash
cd evaluation/multi-modal-evaluation/pawpularity
# Modify --exp, --model_name, --port according to the script parameters
python evaluation-paw.py --exp paw_run --model_name twt --port 8160
```

Other prediction tasks (Adoption, SkinCA, Paintings) have a similar structure — only the data and `ResNet50Predict`'s `task`/weights differ.

## 6. Input/Output & Data Format Summary


| Task Type                                    | Input                                                     | Sandbox Requirements                                 | Answer Format                                           |
| -------------------------------------------- | --------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------- |
| Table QA (WikiTQ/TAT-QA/FinQA/TabMWP, etc.)  | Table header/sample image + question + CSV path           | pandas, standard Python                              | Text/numerical, parsed from `<answer>`                  |
| Table Prediction (classification/regression) | Sample image + task description + table path + image path | pandas, sklearn, `ResNet50Predict(task, image_path)` | Class label or regression value, parsed from `<answer>` |


During evaluation, **the model is not given the full table content directly** — only the table header or sample image and path are provided. Table data must be read by the model through generated code in the sandbox.
